# 联机模式设计方案：实时同房竞速

> 状态：设计稿（v2，含玩法规则修订），未开工。实现前以此文档为准，有变更先改文档。
> 形态：2~8 人同 seed 实时竞速 + 有限赛道冲线制 + 撞墙眩晕重生 + 赛道幽灵车 + 进度条 + 结算排行。部署目标：云服务器。

---

## 1. 核心思路

**薄服务器 + 种子同步 + 状态广播**。服务器不模拟任何游戏逻辑，只做四件事：

1. 房间管理（建房 / 进房 / 准备 / 开局 / 结算）
2. 下发赛道种子（seed）与赛道长度（len）
3. 转发玩家位置快照（pos 消息原样广播）
4. 结算时按冲线时间 / 分数汇总排名

可行性依据（已有地基，全部是现成代码）：

| 地基 | 位置 | 联机中的作用 |
|---|---|---|
| 种子随机 | `core/rng.js`，`G.seed` | 服务器发同一个 seed → 所有客户端生成完全相同的障碍流 |
| 输入指令化 | `core/input.js` → `drainCommands()` | 本地模拟照旧，不需要为联机改造 |
| 事件总线 | `core/bus.js`（`run:start` / `lane:moved` / `run:crash`） | net 层监听语义事件上报，侵入最小 |
| 模式字段 | `core/state.js` `gameMode` | 新增 `'versus'`，与 normal/turbo/auto 并列 |

**为什么不做 lockstep（指令同步）**：lockstep 需要所有人帧帧对齐，一人卡顿全场停。本游戏玩家间无物理交互，各跑各的道，对手位置只是渲染数据——丢了、延迟了都不影响本地手感。竞速类游戏的标准做法就是状态广播。

**为什么服务器不跑模拟**：省掉在服务器复刻游戏逻辑的全部工作与不一致风险；服务器内存占用极低（每房间几十字节状态），一台最低配 VPS 能撑几百房间。

## 2. 玩法规则（versus 模式专属）

这一节是 v2 修订的核心，与单机模式的差异全部在此：

1. **有限赛道，冲线制**：一局赛道固定长度 `len`（v1 取 2500 单位，普通模式全速约 100~120 秒跑完，含 1~2 次撞墙容错）。赛道尽头渲染终点线（发光门框），玩家 z ≥ len 即冲线。**先冲线者赢**；全部冲线或超时后结算。
2. **撞墙不淘汰，眩晕 1 秒**：撞到障碍 → 本地进入眩晕状态 1.0 秒（不可转向、不可加速、音乐能量归零），期间视角轻微抖动 + 车体闪烁；1 秒后自动重生恢复控制。撞墙的代价纯粹是时间（落后一个身位），不是退赛。
3. **重生防二次撞击**（关键安全逻辑，详见 §6.4）：
   - 眩晕期间世界继续滚动 → 把玩家撞上的那面墙"送走"；
   - 重生瞬间扫描重生点前方障碍波，从 4 条车道中选一条**接下来 ≥1 秒内无障碍**的安全车道落位；
   - 重生后附带 0.6 秒无敌闪烁兜底（无敌期间穿过障碍不判定碰撞）。
4. **加速保留**：W 冲刺照常，冲刺拉开距离 = 甩开对手；但撞墙 1 秒眩晕的代价让冲刺变成风险决策——这构成 versus 模式的核心博弈。
5. **进度可见**：
   - 屏幕顶部**赛道进度条**：一条水平线代表全程，每个玩家一枚标记点（颜色 + 名字缩写），实时位置一目了然；
   - HUD 侧边实时排行榜（名次 / 名字 / 进度百分比或分数）。
6. **胜负判定**：
   - 先冲线者名次靠前；冲线时间以**服务器收到 finish 消息的时刻**为准（客户端上报自己 z ≥ len 的瞬间）；
   - 同一 100ms 收包窗口内视为"同时冲线" → **分数高者胜**；分数也相同 → 并列；
   - 超时（`duration` 上限）未冲线者按当前 z（进度）排序，排在所有已冲线者之后；进度也相同按分数。
7. **模式限制**：versus 仅开放普通模式的速度曲线与操作（极速/自动驾驶不参与，同步语义复杂）。
8. **金币**：拾取照旧本地结算（只影响自己的分，不互相抢），冲线平局时金币分起作用 → 鼓励路线选择风险。

## 3. 对局生命周期

```
玩家A 建房(得4位房间码) → 分享给朋友
  玩家B/C/D 输码进房 → 房间面板显示全员
  全员点「准备」→ 服务器发 start{seed, len, startAt, roster, duration}
  → 各客户端 3·2·1 倒计时 → startAt 时刻同时开跑（本地各自模拟）
  → 对局中：每 100ms 上报 pos（含状态字段）；服务器转发；
    本地渲染对手幽灵车（插值）+ 顶部进度条
  → 撞墙者发 crash{z} → 本地眩晕 1s → 重生继续跑（不退赛、不上报淘汰）
  → z ≥ len 时发 finish{time, score} → 服务器记名次，广播
  → 全员冲线 或 单局时长上限(180s)到 → 服务器发 board{final} → 结算界面
  → 「再来一局」全员确认 → 回到准备阶段（换新 seed 与 len）
```

规则细节：

- **掉线 = 判负**：v1 不做断线重连（见 §9）。
- **冲线后**：本地车自动减速滑行 + 变观众视角（可看进度条上别人还在跑）；不再上报 pos。
- **眩晕期间**：继续上报 pos（状态字段 = `stun`），对手能看到你停在那（幽灵车渲染为闪烁状态）。

## 4. 技术选型

| 组件 | 选择 | 说明 |
|---|---|---|
| 服务端 | Node.js ≥ 20 + `ws` | 唯一依赖。不用 Koa/Express（静态托管用 Node 原生 http，WebSocket 用 ws 的 upgrade），单文件可跑 |
| 协议 | JSON 文本帧 | 10Hz × ≤8 人 × ~100B ≈ 单房间 8KB/s，完全够；后续要省带宽再换二进制（ArrayBuffer + DataView），协议层留序列化函数隔离 |
| 客户端连接 | 原生 `WebSocket` API | 不引 Socket.IO（其降级轮询、事件封装对本项目是负资产） |
| 部署 | 单进程：静态托管 `dist/` + WebSocket 同端口 | 前面挂 Nginx 做 TLS（`wss://`）与域名 |

## 6. 消息协议（v2 全量）

所有消息为 JSON：`{t: 类型, ...}`。C→S 客户端发，S→C 服务器发。

### 6.1 大厅 / 房间

| 方向 | 消息 | 字段 | 说明 |
|---|---|---|---|
| C→S | `{t:'create', name}` | | 建房，返回 4 位房间码 |
| C→S | `{t:'join', room, name}` | | 进房 |
| S→C | `{t:'joined', room, you, roster}` | roster: `[{id,name,ready,prog,status}]` | 自己视角进房成功 |
| S→C | `{t:'roster', roster}` | | 房内任何变动（进出/准备）广播 |
| C→S | `{t:'ready', v}` | | 切换准备状态 |
| S→C | `{t:'error', code, msg}` | code: `FULL`/`NO_ROOM`/`IN_GAME`/`NAME` 等 | 拒绝类响应 |

### 6.2 开局

| 方向 | 消息 | 字段 | 说明 |
|---|---|---|---|
| S→C | `{t:'start', seed, len, cd, startAt, roster, duration}` | seed：赛道种子；**len：赛道长度**；**cd：倒计时毫秒**（客户端从收到消息起倒计时，不做时钟换算）；startAt：服务器时钟开跑时刻（仅服务器内部冲线校验用）；duration：单局上限秒数 | 全员就绪即同一时刻广播；客户端收到即开数，cd 毫秒后开跑 |

### 6.3 对局中

| 方向 | 消息 | 字段 | 频率 |
|---|---|---|---|
| C→S | `{t:'pos', z, lane, x, spd, score, st, seq}` | **st：状态（`run`跑动 / `stun`眩晕 / `fin`已冲线）**；seq 自增用于丢包容差 | 10 Hz |
| S→C | `{t:'pos', id, z, lane, x, spd, score, st}` | 服务器打上玩家 id 原样转发（不含 seq） | 广播给其他所有人 |
| C→S | `{t:'crash', z, lane}` | 自己撞墙（眩晕开始） | 每次撞墙一次 |
| S→C | `{t:'crash', id, z}` | 广播某玩家撞墙（幽灵车播放闪烁/停顿表现，**不淘汰**） | |
| C→S | `{t:'finish', score}` | 本地 z ≥ len，冲线（score 为冲线时总分） | 一次 |
| S→C | `{t:'finish', id, rank, time, score}` | 服务器按收到顺序（含同时窗判定）记名次并广播 | |
| S→C | `{t:'board', entries}` | entries: `[{id,name,rank,prog,score,status}]` | 服务器每 2s 聚合广播（进度条/排行榜兜底对齐） |

### 6.4 结算

| 方向 | 消息 | 字段 | 说明 |
|---|---|---|---|
| S→C | `{t:'board', final:true, entries}` | 最终榜：按名次排序（冲线时间 → 同窗比分 → 未冲线按进度 → 再比分） | 全员冲线或超时后 1s 发 |
| C→S | `{t:'again'}` | | 结算界面点「再来一局」= 重新 ready |
| S→C | `{t:'lobby'}` | | 全员同意后房间回准备阶段，下局换新 seed 与 len |

### 6.5 心跳与连接层

- C→S `{t:'ping', ts}` / S→C `{t:'pong', ts}`，间隔 5s；服务器 15s 无任何帧即判掉线踢出。
- 连接级错误码统一走 `error` 消息；WebSocket close 事件在 client.js 内部分类（自己被踢 / 服务器重启 / 网络）。

## 7. 同步机制细节

### 7.1 时间对表（开局同步）

1. **不做时钟换算**（教训：曾用 ping/pong 实测钟偏换算 startAt，但该方案要求服务器与全部客户端同时更新到位，任何一侧跑旧代码就会静默退回错误路径；且玩家本机钟偏可达数秒，`Date.now()` 差值换算直接带入秒级误差）。
2. 服务器全员就绪后**同一时刻广播** `{t:'start', cd}`；客户端**从收到消息那刻起倒计时 cd 毫秒**，到点调用本地 `run:start`（与单机同一入口）。
3. 各端开跑时刻差 = start 消息送达延迟之差（同一机房/地区通常 <50ms，无感）；玩家电脑时钟差多少都完全无影响。ping/pong 仅测 RTT 供网络状况展示。

### 7.2 幽灵车渲染（插值）

- 每个 ghost 维护快照缓冲队列（最近 ~300ms 的 pos 快照）。
- 渲染时刻取 `renderTime = localNow - 100ms`（延迟补偿），在缓冲区两帧之间对 `z/lane/x` 做 lerp；lane 突变（换道）用目标 lane 的动画过渡而非硬切，与本地车的换道手感一致。
- **眩晕中的 ghost**（st=`stun`）：快照 z 不再前进，渲染为原地闪烁 + 车身半透明变红；收到下一个 `run` 状态快照即恢复。
- 缓冲区空（刚开局/丢包）→ 沿用最后已知状态外推（用 spd 推 z，眩晕态则不外推），外推上限 200ms，超限则冻结等新帧。
- 幽灵车样式：本地玩家车的同款模型，半透明 + 玩家名字标签（`THREE.Sprite`）。

### 7.3 位置与本地模拟的关系

- 本地模拟**永远以自己为准**，ghost 只是纯展示，不参与碰撞检测。
- z 轴单位与单机一致（玩家前进距离），不做任何坐标系换算。
- 冲线判定在本地（z ≥ len 即发 finish），服务器只做合理性校验（§10）与排序。

### 7.4 眩晕与重生（本地状态机，撞墙防复撞）

撞墙时刻 t0 的本地流程：

```
撞墙(t0)
  → 冻结输入 1.0s（眩晕）：车体闪烁 + 视角微抖；spd 归零；继续上报 pos(st='stun')
  → 世界照常滚动（障碍后退），原障碍被送离玩家 z 附近
  → t0+1.0s 重生：
     ① 扫描 z_regenerate = t0 时刻玩家的 z（重生点不变，仍原地）
        前方 1.0 秒行程内的所有障碍波（用 obstacles 的生成数据，不依赖实时渲染位置）
     ② 候选 4 条车道，过滤掉"1 秒内会被撞"的道：
        障碍波 z ∈ [z+安全前缘, z+spd_max*1.0s] 且覆盖该车道 → 排除
     ③ 有安全道 → 从中选与当前车道最近的一条（减少无谓横移）
        无安全道（理论罕见）→ 选碰撞时间最晚的道，并提前激活无敌
     ④ 落位 + 无敌 0.6s（车体金色闪烁，期间碰撞判定跳过）
  → 无敌结束，恢复正常，上报 pos(st='run')
```

要点：

- 重生**不回退 z**（撞墙只损失 1 秒时间 + 原地停顿），保证"甩开"的语义成立：领先者撞墙一次 ≈ 落后约 1 个身位。
- 安全区扫描用的是 rng 种子生成的**确定性障碍流**（同 seed 全员一致），与实时滚动的渲染位置解耦，无竞态。
- 眩晕/无敌状态对障碍碰撞判定的开关集中在 controller 的碰撞入口处（两行条件），不影响单机模式（单机撞墙仍是现行行为：结束本局——versus 分支才走眩晕逻辑）。

## 9. 异常与边界

| 场景 | 处理 |
|---|---|
| 掉线（对局中） | 服务器以最后已知进度判其未冲线排名；客户端 WebSocket close → 弹「连接断开」回菜单 |
| 掉线（等待/结算） | 直接从 roster 移除；房主（第一个进房的）掉线则移交第二人 |
| 进房时对局已开始 | 返回 `error IN_GAME`，客户端提示「对局进行中」 |
| 房间无人 | 最后一人的连接关闭即销毁房间，无泄漏 |
| 名字 | 1~12 字符，超长拒绝（`NAME`）；重名自动加后缀编号 |
| 服务器重启 | 所有连接断开，客户端回菜单；房间状态不持久化（v1 可接受） |
| 单局上限 | `duration=180s` 到点未冲线的按进度结算，防挂机占房 |
| 全员眩晕中 | 不影响任何判定（各自本地时间线独立，服务器只收包） |
| finish 上报晚到/丢失 | 服务器以 2s 兜底 board 与超时结算为准；丢一个 finish 包最多影响同窗比分名次精度，下局修正 |

## 10. 防作弊（v1 轻量方案）

薄服务器不模拟，无法严格校验，v1 只做四层便宜的手段：

1. **进度增长率上限**：服务器记录每人最后 z 与时间戳，增速超过理论最大（普通模式速度曲线积分 × 1.2 容差）→ 拒绝该 pos 快照并下发纠正（以服务器最后合法值为准）。
2. **finish 合理性**：finish 的 time 不得早于"理论上最快冲线时间"（按速度曲线积分 len），否则判无效按进度结算。
3. **seed 客户端不可选**：seed 与 len 只由服务器生成下发。
4. **结算以服务器聚合为准**：客户端展示的榜来自 `board`。

认真防作弊（服务器跑模拟复算）不在 v1 范围，文档留坑。

## 11. 部署（云服务器）

```
[玩家浏览器] ─wss://─ [Nginx 443 TLS] ─proxy─ [Node :3000]
                                      ├─ 静态：dist/（vite build 产物）
                                      └─ WebSocket：upgrade 转发
```

- 构建：本地 `vite build` → `dist/` 与 `server/` 一起上服务器。
- 启动：`node server/index.js`（systemd 或 pm2 守护，v1 用 systemd 单服务即可）。
- Nginx 关键配置：`location / { proxy_pass http://127.0.0.1:3000; }` + `proxy_http_version 1.1` + `Upgrade/Connection` 头，静态与 ws 同一域名同一端口路径，客户端连接地址直接用 `wss://${location.host}`。
- 服务器规格：1C1G 起步绰绰有余（转发型负载）。
- 传输：生产强制 `wss`；本地开发 `ws://localhost:3000`。

## 12. 实施阶段（每阶段可独立验收）

1. **协议与服务端骨架**：`server/` 三文件跑通（含 finish 排序逻辑），本地 wscat 手动测进房/准备/开局/转发/冲线。
2. **客户端 net 层**：`src/net/` 两文件 + state 扩展，浏览器控制台可见完整消息流；菜单联机入口能建房进房。
3. **同 seed 有限赛道**：versus 开局用服务器 seed+len，双人同图同长验证一致性；终点线渲染正确。
4. **眩晕与重生**：本地撞墙 → 眩晕 1s → 安全道重生 + 0.6s 无敌；重点测试"重生瞬间不会被同一面墙再撞"（连续撞 20 次统计零复撞）。
5. **幽灵车 + 进度条**：ghost 实体（含 stun 闪烁）+ 插值 + 名字标签 + 顶部全员进度条，双窗口实测延迟下的平滑度。
6. **完整对局闭环**：finish 上报、同窗比分规则、观众态、board 结算、再来一局。
7. **UI 打磨与异常路径**：断线提示、错误码文案、房间面板细节。
8. **部署上线**：Nginx + systemd + wss，真机跨网测试。
